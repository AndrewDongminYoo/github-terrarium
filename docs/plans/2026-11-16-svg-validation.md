# Offline generated-SVG validation

Implement [issue #11](https://github.com/AndrewDongminYoo/github-terrarium/issues/11) under the existing [rendering contract](../specs/architecture.md#rendering-contract) and [acceptance budgets](../specs/terrarium.md#acceptance-criteria).
The operator requested `$pr-loop #11` on 2026-11-16, authorizing implementation, review, PR publication and gated merge.

## Contract and decisions

Add `github_terrarium.validate.validate_svg(raw: bytes) -> None`; reject invalid input with `ValueError` and leave valid bytes unchanged.
This validates the current generator's constrained SVG vocabulary rather than arbitrary SVG or sanitized rewrites.
The renderer, artwork, state/scoring/seed versions and CLI remain unchanged; bundle integration belongs to issue #14.
Use the standard-library XML parser with a bounded tree builder that rejects DTDs and processing instructions before building their contents.
Accept only UTF-8, the SVG namespace, expected element/attribute combinations, internal typed references, finite numeric geometry, and visible direct-root identity/date/stage metadata.
Parse path commands and transform argument counts instead of treating arbitrary strings as geometry.
Accept only the exact trusted ambient stylesheet exported by the renderer, or its complete absence for static output; inline styles allow only a finite animation delay.
Count groups that actually match the allowed stylesheet's animation selectors; a missing stylesheet assigns no animations.
Reject reference cycles and excessive reuse expansion in addition to the 200 KiB / 1,200-element / 40-animation budgets.
Bound nesting to 32 and conservative expanded-reference traversal to 10,000 nodes; numeric magnitudes are limited to 1,000,000, well outside the current scene's range.
These additional limits constrain parser and browser work without adding a dependency.
This change needs no new visual approval because it neither modifies rendering inputs nor changes generated bytes.
